# 08 CI

Tests that only run on one person's machine stop being run. The pipeline runs them the same way for everyone and keeps the results. The workflows here are for GitHub Actions; another system needs the same few commands.

## The workflows

| Workflow | When | What |
|---|---|---|
| `Check` (`.github/workflows/check.yml`) | every pull request, every push to `main` | `npm run check`: types, lint, formatting, the scripts' tests, the secret scan, the inventory against the specs. It does not run the tests against an environment. |
| `Run tests` (`.github/workflows/run-tests.yml`) | when someone starts it | Runs the tests against the environment you choose and keeps the report for 14 days. |

## The accounts in the pipeline

The pipeline has no `.env`. It gets one from a repository secret named `DOTENV`, which holds the same lines as your file:

```bash
gh secret set DOTENV < .env        # from the repository's folder, with the pipeline's accounts in .env
```

or paste the lines under Settings → Secrets and variables → Actions → New repository secret. Use accounts made for the pipeline, not a person's. When an account changes, set the secret again.

## Start a run

On GitHub: Actions → Run tests → Run workflow, then choose:

- **environment:** a file name of `config/environments/`;
- **suite:** `all`, `web` or `api`;
- **grep:** a tag or part of a title, such as `@smoke` or `@TC-031`.

From a terminal: `gh workflow run run-tests.yml -f environment=staging -f grep=@smoke`.

## Read a run

- The job's log lists every test with ✓ or ✘.
- The artifact `playwright-report-<environment>` holds the full report: download it, unzip it, and run `npx playwright show-report <folder>`. A failed test has its screenshot and trace there. A trace holds the session of the test's account (cookies, tokens) and what was on the screen: everyone who can read the repository can download it for 14 days, so keep the repository's readers to the team.
- In the pipeline a failed test is tried once more. A test that passes on the second try is shown as **flaky**: it did not block the run, and it is still a defect of the test. Fix it within the week (`/fix-test`).

## Run on a schedule or after a deployment

When the suite is stable, let it run by itself. Add a schedule next to `workflow_dispatch` in `run-tests.yml`:

```yaml
on:
  workflow_dispatch:
    # the inputs stay as they are
  schedule:
    - cron: '0 4 * * 1-5' # 04:00 UTC, Monday to Friday
```

A scheduled run has no inputs, so give `TEST_ENV` a fallback in the job's `env`: `${{ inputs.environment || 'staging' }}`.

The best moment for the smoke set is right after a deployment to the test environment. Ask whoever owns the deployment pipeline to start this workflow as its last step (`gh workflow run`, or a `repository_dispatch` event).

## Rules for the pipeline

- A red run is looked at the same day. A suite people have learned to ignore is worth nothing.
- Production gets only the read-only smoke set, started by a person.
- Reports are artifacts of a private repository. Do not copy screenshots of real data elsewhere.
- Private repositories have a monthly allowance of pipeline minutes. A browser suite uses them fast: run the smoke set often and the full suite nightly.

## Another CI system

The steps are the same anywhere:

```bash
npm ci
npx playwright install --with-deps chromium
# write .env from the system's secret store
npx playwright test
# keep playwright-report/ as an artifact
```
